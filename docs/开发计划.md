# 开发计划

依据 `docs/项目背景.md`（讨论 #2）整理。本文件是计划的事实源；对应的跟踪 issue 建好后
在此登记编号。

## Scope 评估

**中小型（M）**：预计 2–3 周的零散投入即可拿到「能用」的版本。真正的风险不在代码量，
而在两处未知：

- **代理能不能看到流量** —— Linux 版 WeChat 是否尊重系统/应用代理设置，HTTPS 是否需要
  信任本地 CA。这一步不通，后面全部无从谈起。
- **decrypt.js 能不能脱离 Electron 复用** —— 解密输入来自哪里、是否依赖 Electron 的
  缓存路径或 Node 内置模块。

代码本身没有难点：代理、下载、静态面板都是成熟套路。

**建议：先不写完整 specs，先做一个 spike（里程碑 0）。** spike 结束后再判断：

- 若两处未知都通了 → 直接按里程碑推进，用本文件 + `docs/` 里的协议记录当设计文档即可；
- 若 decode 需要逆向、或需要处理分片/DRM → 那时再为 decoder 单独写一份
  `docs/specs/decoder.md`（需求 + 设计），只为真正复杂的那一块写规格。

## 里程碑

### M0 — spike：打通可行性（最先做，1–2 天）

- [ ] 在本机跑一个最小代理（先 HTTP，再处理 HTTPS/CA），确认能否设置进 WeChat
- [ ] 播放一个视频，把所有请求原样落盘，人工找出媒体请求的 URL 形态
- [ ] 用 Node 直接跑 `decrypt.js`，确认输入输出与依赖
- [ ] 把结论写进 `docs/项目背景.md` 的「待确认的前提」，并更新本计划

**退出标准**：手工串起来，至少成功下载到一个可播放的视频文件。

### M1 — CLI 端到端

- [ ] `wxclip proxy` —— 启动代理，记录候选媒体请求
- [ ] `wxclip decode <url>` —— 调用 JS decoder 得到真实地址
- [ ] `wxclip download <url>` —— 直连下载（不走代理），支持断点与分片合并
- [ ] `wxclip capture` —— 一条命令完成「抓取 → 解码 → 下载」
- [ ] pytest 覆盖：URL 识别、decoder 桥接、下载器（用本地 fixture，不打真实网络）

**退出标准**：一条命令从播放到落盘，`make lint test` 通过。

### M2 — 轻量 web server + 面板

- [ ] 本地 HTTP server：任务列表、当前代理状态、一键下载
- [ ] `web/` 前端页面（保持朴素，够用即可）
- [ ] 与 CLI 复用同一套 `wxclip` 代码，不做第二份实现

**退出标准**：浏览器里能看到捕获到的视频并触发下载。

### M3 — 视频后处理

- [ ] 关键帧截屏（ffmpeg）
- [ ] 文字提取（OCR / 字幕 / 语音转写，先选一条路）
- [ ] 内容总结（调用模型，prompt 与样本进 `evals/`）

**退出标准**：给定一个已下载视频，产出截图集 + 文字 + 一段总结。

## 技术选型（M0 后定稿）

| 环节       | 候选                                   | 取舍要点                                  |
|------------|----------------------------------------|-------------------------------------------|
| 代理       | `mitmproxy` / `proxy.py` / 手写 asyncio | 需不需要 HTTPS 解密；依赖体积             |
| decoder    | Node 子进程跑 `decrypt.js` / 移植成 Python | 先桥接，能跑通再决定要不要移植            |
| 下载       | `httpx` / `aria2c` / `yt-dlp`           | 分片与断点续传谁更省事                    |
| web server | `fastapi + uvicorn` / stdlib            | 面板很薄，别为它引入大框架                |
| 截屏/提取  | `ffmpeg` + OCR 引擎                     | 是否需要本地模型、是否要 GPU              |

## 边界

见 `AGENTS.md` 的 Boundaries：仅限本人客户端已可播放内容的个人使用；不做付费/受限内容的
DRM 破解、不做他人账号批量抓取、不再分发抓取到的媒体。
