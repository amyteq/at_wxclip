# 总结 prompt 的固定样本

判的是**同一段文字喂给同一个 prompt，输出是否还合格**。prompt 本身不在这里 —— 它是 `wxclip/summarize.py` 里的 `SYSTEM_PROMPT`，跟着 wheel 一起装；这里只放输入样本和评判标准。改那段文字之前，先把下面每个样本跑一遍，把输出记进「历次运行」。

## 怎么跑

```bash
# 先看请求本身（不花钱、不需要凭据）
wxclip summarize --text evals/summarize/m0-mac-duo/text.txt --dry-run

# 真跑一次，输出写到 temp/（git 忽略），不要污染样本目录
wxclip summarize --text evals/summarize/m0-mac-duo/text.txt --out temp/eval
```

不带 `--out` 时输出落在样本目录旁边，跑 evals 时记得加上。要比模型/档位就换 `--model` / `--effort`，两者都会写进 `summary.md` 的表头。

值得留的输出复制成 `runs/<日期>-<模型>-<样本>.md`（`runs/` 不进 Git，只把结论记到下面的表里）。

## 样本

| 样本 | 输入 | 考的是什么 |
|------|------|-----------|
| `m0-mac-duo/` | M0 实测片子的真实 OCR 结果（21 行，含误识别） | 能不能从脏文本里还原出正确的一段话 |
| `no-text/` | 空转写 | 没有信息时会不会编 |

两个样本都只有文字：截图不进 Git（见 `docs/directory-guide.md`），要带图跑就用 `wxclip process <视频>` 走完整条路。带图和不带图的差别本身也值得记一笔 —— OCR 把「折叠屏」读成「折玛屏/折私屏/折县」，只有图能纠正它。

### m0-mac-duo

来源：M0 验证用的那条视频号内容（7.48 秒、1080x2344、5 张截屏），`tesseract -l chi_sim+eng --psm 3` 的真实输出，逐行原样保留，没有手工修正。这条片子是一张**文字卡片**——内容全在画面上，没有旁白，正是选 OCR 那条路的理由。

合格的输出要满足：

- **一句话概要**说清是「把 iPhone Duo 的折叠屏透视效果移植到 Mac 的开源工具」；
- 保住这几个事实：项目名 `Mac-Duo`、作者 `Makito`、`15999 元`、`GitHub`、`Apache2.0`、运行在 macOS 菜单栏、实时处理画面；
- **不要**把 OCR 的错字当内容抄进去：`折玛屏`/`折私屏`/`折县手机` 都是「折叠屏」，`了人 GitHub`/`ard GitHub`/`a GitHub` 都是「已上传 GitHub」，`RT SHSM`/`KMS HSM`/`34)`/`Aim, ia` 是噪声，直接丢掉；
- **不要**发明来源里没有的东西：下载量、星标数、发布日期、价格的换算、作者身份。

常见的失败：把 `Apache20` 写成 `Apache 2.0` 之外的协议；把 `15999 元` 说成「售价 15999 元的软件」（原文是被移植的那个**视觉效果**值 15999 元，指的是 iPhone Duo 那台机器）——这一条最能区分「读懂了」和「顺着字面编」。

### no-text

空文件。`build_content` 会写「没有识别到文字」，模型手上什么都没有。合格的输出是**明说无法总结**，长度一两句；出现任何具体内容都算不合格。
